IA · n8n + MCP

n8n como servidor MCP: seus fluxos viram ferramentas do agente de IA

Rhuan Freire · Material de consulta

Um agente de IA só vira útil quando consegue agir nos seus sistemas. O n8n já tem os fluxos prontos; o MCP é a porta padrão para o agente chamá-los. Aqui está o caminho curto e o que travar antes de liberar.

1. A ideia em uma frase

Você monta no n8n um fluxo que expõe ferramentas por um endpoint MCP. Um cliente compatível (como o Claude Code) conecta nesse endpoint, descobre as ferramentas e chama cada uma quando a conversa pede. O fluxo roda no n8n, com as suas credenciais, e devolve o resultado ao agente.

2. Passo a passo

  1. Crie um workflow e adicione o nó MCP Server Trigger. Ele é o ponto de entrada: recebe as chamadas dos clientes MCP.
  2. Ligue ferramentas ao nó. Cada nó de ferramenta conectado ao gatilho vira uma tool que o agente enxerga. Dá para usar nós de ferramenta prontos (HTTP, planilha, banco) ou chamar outro workflow seu como ferramenta.
  3. Descreva cada ferramenta com clareza. O agente escolhe pelo nome e pela descrição. Nome objetivo e uma frase dizendo o que entra e o que sai evitam chamadas erradas.
  4. Defina a autenticação do gatilho (token no cabeçalho). Não deixe o endpoint aberto.
  5. Ative o workflow e copie a URL de produção do nó. É ela que o cliente MCP usa.

3. Conectar no Claude Code

Troque o nome, a URL e o token pelos seus. O tipo de transporte (http ou sse) depende da sua versão do n8n.

claude mcp add --transport http n8n https://SEU-N8N/mcp/ID-DO-WEBHOOK   --header "Authorization: Bearer SEU_TOKEN"

claude mcp list

Confira na documentação: o nome do nó, o formato da URL e as opções de autenticação mudam entre versões do n8n e do cliente. Valide na versão que você usa antes de colocar em produção.

4. Que ferramentas valem a pena

Comece por ações de leitura, que são seguras e já economizam tempo:

  • consultar o status de um atendimento ou pedido;
  • buscar um cliente por telefone ou e-mail;
  • listar as conversas abertas de um canal (por exemplo WhatsApp com Chatwoot);
  • pesquisar na sua base de conhecimento (RAG).

Ações que escrevem (criar ticket, enviar mensagem) entram depois, uma de cada vez, com confirmação humana.

5. Segurança antes de liberar

  • O endpoint exige autenticação e o token não está em repositório nem em print?
  • O agente enxerga só as ferramentas necessárias para a tarefa, e nenhuma que apague ou pague?
  • Ações que enviam, apagam ou cobram pedem confirmação de uma pessoa antes?
  • O retorno de cada ferramenta é tratado como dado não confiável (risco de prompt injection)?
  • Cada ferramenta valida os parâmetros que recebe, em vez de confiar no que o modelo mandou?
  • Há limite de chamadas e log das execuções para investigar se algo sair do esperado?

Se não funcionar

  • O cliente não vê as ferramentas: confirme que o workflow está ativo e que você usou a URL de produção, não a de teste.
  • Erro de autenticação: o cabeçalho tem que bater exatamente com o configurado no gatilho.
  • O agente chama a ferramenta errada: reescreva o nome e a descrição. É o ajuste que mais resolve.
  • Timeout: fluxos longos precisam responder rápido ou devolver um aviso e continuar em segundo plano.
