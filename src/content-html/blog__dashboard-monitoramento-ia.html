O que você precisa medir quando coloca um agente de IA em produção

Rhuan Freire · Abril 2025 · 11 min de leitura

Métricas de software tradicional não bastam para agentes de IA. Aprendi isso da forma mais cara possível — com um agente que "funcionava" e estava custando 40x mais do que eu calculei.

O problema que não aparece no uptime

O agente respondia. Sem erros. Uptime 99,8%. O cliente ficou feliz. Até o mês seguinte, quando chegou a fatura da API.

O que tinha acontecido: o agente estava usando o modelo mais caro para toda e qualquer solicitação, incluindo classificações simples de intenção que um modelo 10x mais barato resolveria igual. Além disso, havia um bug silencioso que causava retries desnecessários em certos tipos de resposta — o agente chamava a API 3 vezes para entregar 1 resposta.

Nenhuma dessas coisas aparecia nas métricas de sistema. Por isso criei um painel dedicado para monitoramento de agentes de IA — e esse artigo é o que aprendi construindo ele.

As 5 métricas que importam

1. Custo por chamada de modelo
Não apenas o custo total — o custo por chamada, por tipo de chamada. Se você tem 3 tipos de operação (classificação, geração de resposta, resumo), precisa saber o custo de cada uma separadamente. Um pico no custo de classificação é um sinal completamente diferente de um pico no custo de geração.

2. Taxa de fallback
Quantas vezes o agente não conseguiu resolver e foi para o fallback (humano, fila, mensagem genérica). Essa métrica mede a eficácia real do agente. Um fallback de 10% é esperado. Um fallback de 40% significa que o agente está falhando — mesmo que todas as chamadas retornem 200 OK.

3. Latência por etapa
Não apenas a latência total de resposta — a latência de cada etapa do pipeline. Se o tempo total aumentou, você precisa saber se foi na transcrição, na chamada ao modelo, no banco de dados ou na geração de resposta. Métricas agregadas escondem o problema.

4. Token usage por tipo de chamada
Prompts grandes custam mais. Se o uso de tokens de um tipo de chamada começa a crescer gradualmente, algo no contexto está sendo injetado onde não deveria — um bug de memória que enche o contexto, um log que está sendo incluído no prompt, um dado de usuário que não precisa estar ali.

5. Retry rate
Quantas chamadas são retries de uma chamada que falhou ou demorou demais. Um retry rate alto indica que a API está instável, que seus timeouts estão calibrados errado, ou — o pior caso — que tem um loop de retry no código que você não colocou.

A estrutura do painel

O painel que construí usa três fontes de dados: logs de aplicação enviados para Postgres via um middleware que intercepta todas as chamadas ao LLM, a API de billing da OpenAI/Anthropic para custo real (não estimado), e as métricas de sistema do servidor.

A coleta é feita via um decorator em Python que envolve qualquer chamada ao modelo:

def track_llm_call(operation_type: str):
    def decorator(func):
        async def wrapper(*args, **kwargs):
            start = time.time()
            try:
                result = await func(*args, **kwargs)
                duration_ms = (time.time() - start) * 1000
                await log_llm_call(
                    operation=operation_type,
                    model=result.model,
                    input_tokens=result.usage.input_tokens,
                    output_tokens=result.usage.output_tokens,
                    duration_ms=duration_ms,
                    status="success"
                )
                return result
            except Exception as e:
                await log_llm_call(operation=operation_type, status="error", error=str(e))
                raise
        return wrapper
    return decorator

Alertas que valem a pena configurar

  • Custo por hora acima de X: alerta imediato se o custo por hora triplicar em relação à média das últimas 24h
  • Taxa de fallback acima de 20%: indica degradação de qualidade do agente
  • P95 de latência acima de 8s: usuário começa a perceber como lento
  • Token médio por chamada crescendo >20% em 1h: possível bug de contexto
  • Retry rate acima de 5%: investiga o padrão antes de virar problema maior

Um agente sem observabilidade é uma caixa-preta que você vai pagar por surpresas.
