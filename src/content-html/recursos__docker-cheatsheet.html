Docker essencial: cheatsheet de comandos e Dockerfile com cache de camadas

Rhuan Freire · Material de consulta

Uma folha de consulta com o que você usa toda semana: containers, imagens, volumes, redes, logs e limpeza. No fim, o Dockerfile que não reinstala tudo a cada mudança.

Containers

docker run -d --name web -p 8080:80 nginx:1.27   # sobe em segundo plano
docker ps                # em execução   (-a mostra todos)
docker logs -f web       # acompanha o log
docker exec -it web sh   # abre um shell dentro
docker stop web          # para
docker start web         # liga de novo (mantém o que gravou)
docker restart web
docker rm web            # remove (apaga a camada de escrita)

Imagens

docker images
docker pull postgres:16
docker build -t meu-app:1.0 .
docker tag meu-app:1.0 registro.exemplo.com/meu-app:1.0
docker push registro.exemplo.com/meu-app:1.0
docker rmi meu-app:1.0

Volumes e redes

docker volume create dados
docker run -d -v dados:/var/lib/postgresql/data postgres:16
docker volume ls
docker volume rm dados

docker network create proxy
docker network ls
docker network inspect proxy

Compose

docker compose up -d          # sobe tudo (--build recompila)
docker compose ps
docker compose logs -f app
docker compose down           # derruba (mantém volumes)
docker compose down -v        # derruba e apaga os volumes

Limpeza

docker system df              # quanto espaço o Docker usa
docker container prune        # containers parados
docker image prune            # imagens sem tag
docker system prune           # parados, redes e imagens sem uso

Cuidado: docker system prune -a remove todas as imagens sem container associado, e docker compose down -v apaga volumes. Confira antes de rodar em produção.

Dockerfile que aproveita o cache

O Docker guarda cada instrução em uma camada. Se uma camada muda, todas as seguintes são refeitas. Por isso as dependências vêm antes do código: mexer num arquivo seu não reinstala tudo.

FROM node:22-alpine
WORKDIR /app

COPY package*.json ./
RUN npm ci

COPY . .
CMD ["node", "server.js"]

.dockerignore

Sem ele, tudo entra no contexto do build: fica lento e pode parar dentro da imagem.

node_modules
.git
.env

Reiniciar não é remover

Reiniciar o container mantém o que ele gravou. docker rm apaga a camada de escrita. O que precisa sobreviver vai em volume.

Checklist rápido

  • A imagem tem versão fixa (node:22-alpine), não latest?
  • Dependências copiadas e instaladas antes do COPY . .?
  • Existe .dockerignore com .env e .git?
  • Os dados importantes estão em volume?
  • Segredos fora da imagem e fora do compose versionado?

Precisa disso rodando no seu ambiente? Posso olhar o seu caso e montar com você.
