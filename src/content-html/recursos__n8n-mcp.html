n8n com MCP nativo: ligue na instância e conecte no Claude Code

Rhuan Freire · Material de consulta

O n8n traz um servidor MCP embutido. Em poucos cliques você escolhe quais workflows um agente de IA pode usar e conecta o Claude Code por OAuth. Aqui está o caminho curto e o que travar antes de liberar.

Guia completo para baixar: o passo a passo do zero, desde ligar o MCP no n8n até conectar no Claude Code, com o checklist de segurança e os erros comuns. Baixar o PDF · Baixar em Markdown

1. A ideia em uma frase

Você liga o MCP da instância no n8n, escolhe quais workflows ficam disponíveis e conecta um cliente (como o Claude Code). O agente passa a ver e rodar só esses workflows, com as credenciais que já estão no n8n.

2. Ligar o MCP no n8n

  1. Entre como dono ou administrador e abra Settings > Instance-level MCP.
  2. Em Connection details, deixe o MCP status em Enabled.
  3. Em Access > Workflows exposed, escolha quais workflows o cliente pode usar. Nenhum fica exposto por padrão.
  4. Deixe Auto-expose new workflows desligado, para um workflow novo não ficar acessível sem você decidir.
  5. Clique em Connect. A janela Connect a client mostra o Server URL e as duas formas de entrar: OAuth (recomendado) e API key.

O Server URL termina em /mcp-server/http, por exemplo https://seu-n8n.com.br/mcp-server/http. Copie da janela, não da barra de endereço do navegador.

3. Conectar no Claude Code

Com OAuth (recomendado):

claude mcp add --transport http n8n https://SEU-N8N/mcp-server/http

Depois, dentro do Claude Code, rode /mcp, escolha n8n e aprove o acesso no navegador. Para conferir: claude mcp list.

Com chave de API, no lugar do OAuth:

claude mcp add --transport http n8n-mcp https://SEU-N8N/mcp-server/http   --header "Authorization: Bearer SEU_TOKEN"

Token só aparece uma vez. Guarde em um gerenciador de senhas. Gerar outro revoga o anterior na hora. Se salvar a configuração em .mcp.json do projeto, use variável de ambiente, nunca o token escrito no arquivo.

4. Primeiro teste

Peça algo de leitura ao Claude, como "liste os workflows do n8n disponíveis para você". Só depois exponha workflows que enviam mensagem, gravam ou apagam, um de cada vez.

5. Segurança antes de liberar

  • Só os workflows necessários estão em Workflows exposed, e Auto-expose está desligado?
  • Você revisou Connected clients e, se possível, restringiu Allowed callback URLs (o padrão, All, é menos seguro)?
  • Workflows que enviam, apagam ou cobram pedem confirmação de uma pessoa antes?
  • O retorno dos workflows é tratado como dado não confiável (risco de prompt injection)?
  • Cada workflow valida os parâmetros que recebe, em vez de confiar no que o modelo mandou?
  • Você sabe revogar? Em MCP status, escolher Disable desconecta todos os clientes.

Se não funcionar

  • "You do not have sufficient permissions to authorize this request": o acesso MCP está desligado ou você não é dono/administrador.
  • O Claude conecta, mas não vê workflows: o workflow não está em Workflows exposed.
  • Erro 401 ou 403 com chave de API: o cabeçalho tem que ser idêntico ao token gerado; se você gerou outro, o antigo foi revogado.
  • Conexão pendurada atrás de proxy: desligue o buffer de proxy no endpoint MCP (no nginx, proxy_buffering off).

Alternativa: ferramentas sob medida com o nó MCP Server Trigger

Se você quer expor só um conjunto pequeno de ferramentas dentro de um workflow, o n8n também tem o nó MCP Server Trigger, que usa uma URL própria e autenticação Bearer ou Header. O guia para baixar descreve esse caminho também.
